# 一、爬虫基础与原理

## 1. 什么是网络爬虫？简述其工作原理。

**精简回答**：网络爬虫（Web Crawler），又称网络蜘蛛（Web Spider），是一种自动化程序，用于在互联网上自动抓取网页内容。

其工作原理大致分为四个步骤：发送请求、接收响应、解析页面、存储数据。

```
用户/任务 → 获取初始URL → 发送HTTP请求 → 接收服务器响应 → 解析数据 → 提取目标信息 → 存储 → 提取新URL → 继续爬取
```

**原理展开**：

```python
# 爬虫的四个核心步骤
import requests
from bs4 import BeautifulSoup

# 1. 发送请求
url = "https://example.com"
headers = {"User-Agent": "Mozilla/5.0"}
response = requests.get(url, headers=headers)

# 2. 接收响应（状态码、响应体）
print(response.status_code)  # 200 表示成功
print(response.encoding)      # 自动检测编码

# 3. 解析页面
soup = BeautifulSoup(response.text, "html.parser")
data = soup.find_all("div", class_="content")

# 4. 存储数据
with open("data.json", "w") as f:
    f.write(str(data))
```

简单来说，爬虫就是用代码代替浏览器，自动完成“请求-响应-解析-存储”的过程。


## 2. 请简述爬虫抓取网页的完整 HTTP 请求响应过程。

**精简回答**：在面试中被问到这一题，可以从 DNS 解析 -> TCP 连接 -> 发送 HTTP 请求 -> 服务器处理 -> 返回响应 -> 浏览器渲染/爬虫解析 的全链路角度来回答。

```
第一步：用户在浏览器输入 URL 或在爬虫中设置目标 URL
第二步：DNS 解析，将域名转换为 IP 地址
第三步：建立 TCP 连接（HTTP 三次握手）
第四步：客户端发送 HTTP 请求报文（请求行、请求头、请求体）
第五步：服务器接收请求并处理
第六步：服务器返回 HTTP 响应报文（状态行、响应头、响应体）
第七步：如果是浏览器，渲染页面；如果是爬虫，解析响应内容
第八步：关闭 TCP 连接（四次挥手）
```

爬虫本质上就是自动化了这一过程，用代码代替人工完成请求和解析步骤。


## 3. 深度优先搜索（DFS）和广度优先搜索（BFS）在爬虫中如何应用？

**精简回答**：DFS 和 BFS 是图遍历的两种基本策略。

| 算法 | 策略                                           | 爬虫应用场景                                         | 存储结构      |
| ---- | ---------------------------------------------- | ---------------------------------------------------- | ------------- |
| DFS  | 沿着一条分支尽可能深地探索，直到叶子节点再回溯 | 深入探索某一特定领域，如追踪所有链接到某一主题的页面 | 栈（Stack）   |
| BFS  | 先访问所有相邻节点，再逐层向外扩展             | 广度覆盖整个网站，抓取首页链接后逐层深入             | 队列（Queue） |

```python
from collections import deque

# BFS 爬虫（更常用，避免爬得太深）
def bfs_crawler(start_url):
    queue = deque([start_url])
    visited = set()

    while queue:
        url = queue.popleft()
        if url in visited:
            continue
        visited.add(url)

        # 获取页面中的所有链接
        links = extract_links(url)
        queue.extend(links)

# DFS 爬虫
def dfs_crawler(url, visited, depth=3):
    if depth == 0 or url in visited:
        return
    visited.add(url)
    for link in extract_links(url):
        dfs_crawler(link, visited, depth-1)
```

> 实际应用中，BFS 更适合于需要广度覆盖的场景，如抓取一个网站的所有首页链接，再逐步深入到子页面；DFS 则适用于需要深入探索某一特定领域的场景。

**面试高频追问**：BFS 为什么比 DFS 更常用？—— BFS 可以更好地控制爬取层级，避免爬得太深；同时更适合分布式调度（队列天然支持并发）；更符合人类浏览网页的习惯（先看首页再到详情页）。


# 二、HTTP/HTTPS 协议与网络基础

## 4. GET 和 POST 请求有什么区别？

**精简回答**：这是爬虫面试中出现频率最高的基础题之一。

| 对比维度     | GET                      | POST                 |
| ------------ | ------------------------ | -------------------- |
| 请求方式     | 从服务器获取数据         | 向服务器提交数据     |
| 参数位置     | URL 查询字符串中         | 请求体中             |
| 参数长度限制 | 有（URL 长度限制）       | 无（理论上）         |
| 安全性       | 参数可见，安全性低       | 参数不可见，相对安全 |
| 缓存         | 可被浏览器缓存           | 不可缓存             |
| 幂等性       | 幂等（多次请求结果相同） | 非幂等               |
| 适用场景     | 查询、搜索、分页         | 登录、注册、数据提交 |

**原理展开**：

```python
import requests

# GET 请求：参数在 URL 中
response = requests.get("https://api.example.com/users?id=123")
print(response.url)  # https://api.example.com/users?id=123

# POST 请求：参数在请求体中
data = {"username": "alice", "password": "123456"}
response = requests.post("https://api.example.com/login", data=data)
```

> 除了常规的区别外，还需提到 GET 请求会被浏览器缓存，而 POST 请求更适合敏感数据传输。


## 5. HTTP 常见状态码有哪些？各自的含义是什么？

**精简回答**：

| 状态码范围 | 类别       | 含义                       |
| ---------- | ---------- | -------------------------- |
| 1xx        | 信息响应   | 请求已接收，继续处理       |
| 2xx        | 成功响应   | 请求成功处理               |
| 3xx        | 重定向     | 需要进一步操作才能完成请求 |
| 4xx        | 客户端错误 | 请求有语法错误或无法完成   |
| 5xx        | 服务器错误 | 服务器处理请求出错         |

**常见状态码详解**：

| 状态码 | 含义           | 爬虫应对策略                 |
| ------ | -------------- | ---------------------------- |
| 200    | 请求成功       | 正常解析响应内容             |
| 301    | 永久重定向     | 更新 URL 到新地址            |
| 302    | 临时重定向     | 跟随 Location 头             |
| 400    | 请求参数错误   | 检查请求头/参数格式          |
| 401    | 未授权         | 添加认证信息（token/cookie） |
| 403    | 禁止访问       | 可能需要代理或调整请求头     |
| 404    | 页面不存在     | URL 已失效，跳过             |
| 429    | 请求过多       | 降低请求频率，加延时         |
| 500    | 服务器内部错误 | 稍后重试                     |


## 6. Cookie 和 Session 的作用及区别是什么？爬虫中如何处理？

**精简回答**：

| 对比维度 | Cookie                 | Session                |
| -------- | ---------------------- | ---------------------- |
| 存储位置 | 客户端（浏览器）       | 服务器端               |
| 存储容量 | 小（4KB 左右）         | 大（无硬性限制）       |
| 安全性   | 较低（可被篡改）       | 高                     |
| 有效期   | 可灵活设置             | 通常较短（如 30 分钟） |
| 主要用途 | 记录用户偏好、会话标识 | 存储用户认证状态       |

**爬虫中的应用**：

```python
# 方法1：手动在 headers 中添加 Cookie
headers = {"Cookie": "sessionid=abc123; user_id=456"}
response = requests.get(url, headers=headers)

# 方法2：使用 requests.Session 自动保持 Cookie
session = requests.Session()
session.post("https://example.com/login", data={"user": "alice", "pwd": "123"})
# 后续请求会自动携带 Session 中保存的 Cookie
response = session.get("https://example.com/user/dashboard")
```

Cookie 存储在客户端，Session 存储在服务器，常用于用户状态管理。爬虫中可能需要模拟登录，因此理解 Cookie 的传递机制和 Session 的维持至关重要。


## 7. HTTPS 是如何保证数据传输安全的？

**精简回答**：HTTPS = HTTP + SSL/TLS，通过**非对称加密 + 对称加密 + 数字证书**的机制保证通信安全。

```
┌─────────────────────────────────────────────────────────────────┐
│                       HTTPS 握手流程                            │
├─────────────────────────────────────────────────────────────────┤
│ 1. 客户端发起 HTTPS 请求（Client Hello）                        │
│                          ↓                                      │
│ 2. 服务器返回数字证书（Server Hello + 证书）【包含公钥】         │
│                          ↓                                      │
│ 3. 客户端验证证书合法性（CA 签名校验）                          │
│                          ↓                                      │
│ 4. 客户端生成随机对称密钥，用服务器的公钥加密后发送              │
│                          ↓                                      │
│ 5. 服务器用私钥解密获取对称密钥                                 │
│                          ↓                                      │
│ 6. 后续通信使用对称加密传输数据                                 │
└─────────────────────────────────────────────────────────────────┘
```

**爬虫中的注意事项**：
- 使用 `verify=False` 可跳过 SSL 证书验证（不推荐在生产环境使用）
- 对于 SSL Pinning（证书锁定）的 APP，需使用 Frida 等工具绕过校验

```python
import requests

# 跳过 SSL 验证（可能产生安全警告）
response = requests.get("https://example.com", verify=False)

# 携带客户端证书
response = requests.get("https://example.com", cert=("client.crt", "client.key"))
```


## 8. HTTP 请求头中哪些字段对爬虫比较重要？

**精简回答**：

| 请求头字段                   | 作用                        | 爬虫注意事项                                  |
| ---------------------------- | --------------------------- | --------------------------------------------- |
| `User-Agent`                 | 标识客户端类型              | 必须伪装成真实浏览器，避免使用 Python 默认 UA |

| `Accept` / `Accept-Language` | 声明接受的响应类型          | 根据目标网站配置                              |
| `Authorization`              | 身份认证（如 Bearer token） | API 调用时常用                                |
| `X-Requested-With`           | 标识 Ajax 请求              | 某些网站会校验                                |
| `Origin`                     | 标识请求来源域名            | CORS 相关                                     |
| `Content-Type`               | 标识请求体格式              | POST 请求时需正确设置                         |


# 三、Python 请求库

## 9. requests 库和 urllib 库有什么区别？为什么选择 requests？

**精简回答**：面试中要体现出你对这两个库的优劣有清晰的认识。

| 对比维度     | requests                  | urllib                   |
| ------------ | ------------------------- | ------------------------ |
| 语法复杂度   | 简洁直观                  | 相对繁琐                 |
| Session 管理 | 内置 `requests.Session()` | 需手动处理 Cookie 和连接 |
| 自动编码     | 自动处理 JSON、gzip 等    | 需手动调用方法           |
| 异常处理     | 更友好的异常体系          | 异常分类较细             |
| 依赖         | 第三方库，需安装          | Python 标准库，无需安装  |

**代码对比**：

```python
# urllib 方式（标准库）
from urllib import request, parse

data = parse.urlencode({"key": "value"}).encode()
req = request.Request("https://api.example.com", data=data, headers={"User-Agent": "..."})
response = request.urlopen(req)
html = response.read().decode()

# requests 方式（第三方库，更简洁）
import requests

response = requests.post("https://api.example.com", data={"key": "value"}, headers={"User-Agent": "..."})
html = response.text
```

requests 库语法更简洁，支持 Session 对象、自动 Cookie 管理、连接池复用，是日常爬虫的首选。


## 10. 如何使用 requests 库保持会话（Session）？Session 的工作原理是什么？

**精简回答**：`requests.Session` 对象在多个请求之间保持状态，让 Cookie 持久化并复用底层 TCP 连接。

```python
import requests

# 创建 Session 对象
session = requests.Session()

# 登录
session.post("https://example.com/login", data={"username": "alice", "password": "123"})

# 后续请求自动携带登录时设置的 Cookie
response = session.get("https://example.com/dashboard")

print(response.cookies)  # 查看当前 Session 中的 Cookie
```

**Session 的工作原理**：

1. Session 对象内部维护了一个 `CookieJar`，自动处理 Cookie 的存储和发送
2. 使用 `urllib3` 的连接池，复用 TCP 连接（HTTP Keep-Alive）
3. 可设置默认 headers（`session.headers.update()`），所有请求都会继承

HTTP 协议本身是无状态的，Session 通过在多个请求之间维持 Cookie 和复用连接，实现了“有状态的”请求体验。

**面试加分点**：大数据量爬取时，应使用 Session 而非每次新建 `requests.get()`，这样可以复用 TCP 连接，显著减少握手开销。


## 11. requests 中如何设置代理？如何搭建和使用代理池？

**精简回答**：通过 `proxies` 参数设置代理，代理池则是预先存储多个可用代理，请求时随机选择。

```python
import requests

# 单个代理设置
proxies = {
    "http": "http://127.0.0.1:8080",
    "https": "https://127.0.0.1:8080"
}
response = requests.get("https://example.com", proxies=proxies)

# 代理池的核心实现
from random import choice
import redis

class ProxyPool:
    def __init__(self):
        self.redis_client = redis.Redis(host='localhost', port=6379)

    def get_proxy(self):
        """从 Redis 中随机获取一个可用代理"""
        proxy = self.redis_client.srandmember('proxies')
        return proxy.decode() if proxy else None

    def add_proxy(self, proxy):
        self.redis_client.sadd('proxies', proxy)

# 使用代理池
proxy_pool = ProxyPool()
proxy = proxy_pool.get_proxy()
response = requests.get(url, proxies={"http": f"http://{proxy}"})
```

使用代理 IP 池轮换是突破 IP 限制封禁的主要手段，同时在 Scrapy 中可通过 Downloader Middleware 动态切换代理。


## 12. requests 中如何设置超时和重试？为什么需要设置？

**精简回答**：

```python
import requests
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

# 方式1：基础超时设置（连接超时 + 读取超时）
response = requests.get("https://api.example.com", timeout=(3, 10))  # (connect, read)

# 方式2：自定义重试策略
session = requests.Session()
retry = Retry(
    total=3,                # 最多重试 3 次
    backoff_factor=1,       # 重试间隔：1s, 2s, 4s...
    status_forcelist=[500, 502, 503, 504]  # 遇到这些状态码重试
)
adapter = HTTPAdapter(max_retries=retry)
session.mount('http://', adapter)
session.mount('https://', adapter)
```

设置超时可以避免请求长期挂起导致的程序卡死；设置重试可以应对网络抖动或服务器临时故障，提高爬虫的稳定性。

**避坑点**：`timeout` 参数设置过小容易在网络波动时失败，设置过大会降低效率，一般连接超时 3-5 秒、读取超时 10-30 秒较为合理。


# 四、数据解析

## 13. BeautifulSoup 和 lxml 有什么区别？如何选择？

**精简回答**：BeautifulSoup 因其易用性和灵活性广受欢迎，适合快速开发；lxml 以其速度和效率著称，适合处理大规模数据。

| 对比维度   | BeautifulSoup                          | lxml                    |
| ---------- | -------------------------------------- | ----------------------- |
| 解析速度   | 较慢（纯 Python）                      | 快（底层 C 语言）       |
| 易用性     | API 直观，上手快                       | 相对复杂                |
| 容错能力   | 强大（可解析不规范 HTML）              | 较强                    |
| 功能丰富度 | 支持多种解析器（lxml, html.parser 等） | 专注于 XPath/CSS 选择器 |
| 适用场景   | 开发调试、复杂页面                     | 生产环境、大规模数据    |

```python
from bs4 import BeautifulSoup
from lxml import etree

# BeautifulSoup 方式
soup = BeautifulSoup(html, "lxml")  # 也可以指定 html.parser
title = soup.find("h1").text
links = soup.select("a[class='content']")

# lxml 方式（XPath）
tree = etree.HTML(html)
title = tree.xpath("//h1/text()")[0]
links = tree.xpath("//a[@class='content']/@href")
```

**选择建议**：
- 快速原型开发 → BeautifulSoup
- 大规模数据采集生产环境 → lxml
- 两者可以结合使用：用 lxml 做解析器传给 BeautifulSoup


## 14. XPath 和 CSS 选择器各有什么优缺点？如何选择？

**精简回答**：

| 对比维度   | XPath                           | CSS 选择器           |
| ---------- | ------------------------------- | -------------------- |
| 语法复杂度 | 较复杂，功能更强大              | 简洁，前端开发者熟悉 |
| 定位能力   | 支持反向查找（parent/ancestor） | 只能向下查找         |
| 文本提取   | 内置 `text()` 函数              | 需额外处理           |
| 属性匹配   | 灵活（`[@class='value']`）      | 支持多种选择器       |
| 执行速度   | 略快                            | 略慢                 |

```python
# XPath 的强大能力
//div[@class='article']//a[contains(@href, 'detail')]/text()  # 包含匹配
//div/parent::section   # 向上查找父级
//span[position()>2]    # 位置过滤

# CSS 选择器的简洁性
div.article a         # 类名筛选
#main > .content      # 直接子级
a[href^="https"]      # 属性前缀匹配
```

**选择建议**：
- 简单页面结构 → CSS 选择器
- 复杂层级/向上查找 → XPath
- 团队技术栈：前端转爬虫的同学用 CSS 更顺手，后端同学可能更倾向 XPath


## 15. 正则表达式在爬虫中如何应用？常用元字符有哪些？

**精简回答**：

| 元字符          | 含义                           | 示例                           |
| --------------- | ------------------------------ | ------------------------------ |
| `.`             | 匹配任意单个字符（除换行符）   | `a.c` 匹配 `abc`               |
| `^`             | 匹配字符串开头                 | `^hello`                       |
| `$`             | 匹配字符串结尾                 | `world$`                       |
| `*`             | 匹配前一个字符 0 次或多次      | `ab*c` → `ac` / `abc` / `abbc` |
| `+`             | 匹配前一个字符 1 次或多次      | `ab+c` → `abc` / `abbc`        |
| `?`             | 匹配前一个字符 0 次或 1 次     | `ab?c` → `ac` / `abc`          |
| `\d`            | 匹配任意数字                   | `\d{4}-\d{2}-\d{2}` 匹配日期   |
| `\w`            | 匹配字母、数字、下划线         | `\w+` 匹配单词                 |
| `\s`            | 匹配空白字符（空格、制表符等） | `hello\sworld`                 |
| `[]`            | 匹配括号中的任意字符           | `[a-z]` 匹配小写字母           |
| `()`            | 分组捕获                       | `(abc)+`                       |
| `(?P<name>...)` | 命名分组                       | 提取 JSON 字段                 |

**Python 示例**：
```python

# 提取价格

print(price.group(1))  # '128.00'

# 提取邮箱
emails = re.findall(r'\w+@\w+\.\w+', text)
```

> 正则表达式匹配任意一个数字的字符是 `\d`，匹配任意单个字符的元字符是 `.`。

# 五、Scrapy 框架

## 17. Scrapy 框架的架构是什么？五大组件和两大中间件分别是什么？

**精简回答**：Scrapy 是基于 Twisted 异步网络框架开发的 Python 爬虫框架，使用非阻塞（异步）代码实现并发。

**五大组件**：

| 组件                      | 职责                                                       |
| ------------------------- | ---------------------------------------------------------- |
| **Engine（引擎）**        | 框架核心，处理整个系统的数据流，触发事务                   |
| **Scheduler（调度器）**   | 接收 Engine 的 Request，去重后加入队列，供 Engine 再次请求 |
| **Downloader（下载器）**  | 下载网页内容，返回 Response 给 Engine                      |
| **Spider（爬虫）**        | 解析 Response，提取 Item 和新的 Request                    |
| **Item Pipeline（管道）** | 处理 Spider 提取的 Item（数据清洗、去重、存储）            |

**两大中间件**：
- **Downloader Middleware**：位于 Engine 和 Downloader 之间，用于处理请求和响应的预处理（如代理切换、UA 伪装）
- **Spider Middleware**：位于 Engine 和 Spider 之间，用于处理 Spider 的输入和输出

**数据流**：
```
Spiders → Engine → Scheduler → Engine → Downloader → Engine → Spiders
   ↑                                    ↓
   └─────────────── Engine ←────────────┘
                      ↓
              Item Pipeline
```


## 18. Scrapy 的基本工作流程是怎样的？

**精简回答**：Scrapy 的数据流转分为 9 个步骤：

```
1. Spider 从 start_urls 或 start_requests() 生成初始 Requests
2. Spider 将 Requests 发送给 Engine
3. Engine 将 Requests 发送给 Scheduler
4. Scheduler 将 Requests 放入队列
5. Scheduler 将下一个 Request 发送给 Engine
6. Engine 将 Request 交给 Downloader 下载
7. Downloader 返回 Response 给 Engine
8. Engine 将 Response 返回给 Spider 的 parse 方法解析
9. Spider 解析后 yield Item（交 Pipeline）或新 Request（回到步骤 2）
```

**代码示例**：
```python
import scrapy

class ExampleSpider(scrapy.Spider):
    name = "example"
    start_urls = ["https://example.com/page/1"]

    def parse(self, response):
        # 提取数据
        for item in response.css("div.content"):
            yield {
                "title": item.css("h2::text").get(),
                "price": item.css(".price::text").get()
            }

        # 提取下一页
        next_page = response.css("a.next::attr(href)").get()
        if next_page:
            yield response.follow(next_page, self.parse)
```


## 19. Scrapy 如何实现数据去重？如何自定义去重规则？

**精简回答**：Scrapy 默认使用**基于集合的内存去重**，通过 `RFPDupeFilter` 类实现。

**去重原理**：
1. 对每个 Request 的 URL 生成一个**指纹（fingerprint）**
2. 默认指纹 = `hash(url)`
3. 将指纹存入 Python 的 `set()` 数据结构
4. 新请求生成指纹后与 `set()` 比对，存在则丢弃

```python
# 自定义去重规则 - 重写 request_fingerprint 方法
from scrapy.dupefilters import RFPDupeFilter
from w3lib.url import canonicalize_url

class CustomDupeFilter(RFPDupeFilter):
    def request_fingerprint(self, request):
        # 忽略查询参数中的时间戳，只关注核心 URL
        url = canonicalize_url(request.url, keep_blank_values=True)
        return hashlib.sha256(url.encode()).hexdigest()
```

**更优方案 - Redis 布隆过滤器去重**（适合分布式）：
```python
import redis
import hashlib

class BloomFilterDupeFilter:
    def __init__(self, redis_client, key='requests_seen', bit_size=1 << 20):
        self.redis = redis_client
        self.key = key
        self.bit_size = bit_size

    def request_seen(self, request):
        fp = hashlib.md5(request.url.encode()).hexdigest()
        offset = int(fp, 16) % self.bit_size
        if self.redis.getbit(self.key, offset):
            return True
        self.redis.setbit(self.key, offset, 1)
        return False
```

## 28. 如何应对网站返回 403/404/429 状态码？

**精简回答**：

| 状态码  | 含义               | 应对策略                                                 |
| ------- | ------------------ | -------------------------------------------------------- |
| **403** | 禁止访问（反爬）   | 检查/修改请求头，使用代理 IP，降低频率，换 UA            |
| **404** | 页面不存在         | URL 已失效，跳过处理，记录日志                           |
| **429** | 请求过多（太频繁） | 延长延时（指数退避），使用代理 IP 轮换，暂停一段时间重试 |

```python
# 指数退避处理
import time

def fetch_with_retry(url, max_retries=5):
    for i in range(max_retries):
        response = requests.get(url)
        if response.status_code == 200:
            return response
        elif response.status_code == 429:
            wait_time = 2 ** i  # 2, 4, 8, 16, 32 秒
            print(f"请求过多，等待 {wait_time} 秒后重试...")
            time.sleep(wait_time)
        else:
            time.sleep(1)
    return None
```

# 七、异步爬虫与高性能

## 30. 爬虫中使用多线程好还是多进程好？各有什么优缺点？

**精简回答**：

对于爬虫这种 **IO 密集型** 场景，多线程通常比多进程更适合。

```python
# 多线程示例
from concurrent.futures import ThreadPoolExecutor

def fetch_url(url):
    return requests.get(url).status_code

with ThreadPoolExecutor(max_workers=10) as executor:
    results = list(executor.map(fetch_url, urls))
```

| 对比维度       | 多线程                          | 多进程              |
| -------------- | ------------------------------- | ------------------- |
| **GIL 影响**   | 有，但不影响 IO 操作            | 无影响，进程独立    |
| **内存占用**   | 低（共享内存）                  | 高（独立内存）      |
| **创建开销**   | 小                              | 大                  |
| **通信复杂度** | 容易（共享变量）                | 复杂（需队列/Pipe） |
| **适用场景**   | IO 密集型（网络请求、文件读写） | CPU 密集型          |

对于 IO 密集型代码，多线程在 IO 等待时自动切换到其他线程，不浪费 CPU 资源，从而提升程序执行效率。


## 31. asyncio + aiohttp 实现异步爬虫的原理是什么？

**精简回答**：asyncio 基于事件循环，在遇到网络 IO（如 `await session.get()`）时挂起当前协程，切换到其他就绪协程，实现单线程高并发。

```python
import asyncio
import aiohttp

async def fetch(session, url):
    async with session.get(url) as response:
        return await response.text()

async def main():
    async with aiohttp.ClientSession() as session:
        tasks = [fetch(session, f"https://example.com/page/{i}") for i in range(100)]
        responses = await asyncio.gather(*tasks)  # 100 个请求并发执行
        print(f"完成 {len(responses)} 个请求")

asyncio.run(main())
```

**多线程 vs 异步性能对比**：
- 多线程：1000 个请求，约 10 秒（受限于线程数）
- 异步：1000 个请求，约 2-3 秒（单线程事件驱动）

**注意事项**：
- `aiohttp` 必须与 `asyncio` 配合使用
- `requests` 库不支持异步（阻塞），需替换为 `aiohttp` 或 `httpx`


## 32. Scrapy 实现并发的原理是什么？不用框架如何实现高并发？

**精简回答**：

Scrapy 使用 **Twisted 异步网络框架**实现非阻塞并发，通过 Reactor 模式在单线程内处理大量并发请求。

```python
# 不用框架实现高并发爬取
# 方案1：asyncio + aiohttp
# 方案2：concurrent.futures + ThreadPoolExecutor
from concurrent.futures import ThreadPoolExecutor, as_completed

def crawl_batch(urls, max_workers=20):
    with ThreadPoolExecutor(max_workers=max_workers) as executor:
        future_to_url = {executor.submit(requests.get, url): url for url in urls}
        for future in as_completed(future_to_url):
            url = future_to_url[future]
            try:
                response = future.result()
                print(f"{url}: {response.status_code}")
            except Exception as e:
                print(f"{url} 失败: {e}")
```

## 34. JS 逆向的基本思路是什么？如何处理请求参数加密？

**精简回答**：JS 逆向是爬虫进阶的核心能力，基本思路为：**抓包定位 → JS 代码定位 → 断点调试 → 算法还原 → Python 复现**。

```javascript
// 浏览器开发者工具抓包，找到加密请求
// 假设发现加密参数 sign = CryptoJS.MD5(token + timestamp)

// Python 复现加密逻辑
import hashlib
import time

def generate_sign(token):
    timestamp = str(int(time.time()))
    raw = token + timestamp
    sign = hashlib.md5(raw.encode()).hexdigest()
    return sign, timestamp
```

**具体流程**：
1. 打开浏览器开发者工具 → Network 面板
2. 找到目标请求 → 复制其 URL、headers、参数
3. 搜索加密参数名（如 `sign`、`token`、`_signature`）定位 JS 代码位置
4. 在 Sources 面板中添加断点，跟踪加密逻辑
5. 找到加密函数后，复制/翻译为 Python 代码
6. 测试验证一致性

**JS 逆向常用工具**：
- Charles / Fiddler：抓包分析
- Chrome DevTools：JS 调试
- AST：还原混淆代码
- PyExecJS / PyMiniRacer：Python 中执行 JS 代码


## 35. 字体反爬是如何实现的？如何破解？

**精简回答**：字体反爬是网站将字符（如数字、价格）映射为自定义字体，网页显示正常，但源代码中为乱码或特殊编码，防止直接抓取文本内容。

**破解步骤**：

```python
from fontTools.ttLib import TTFont

# 在 CSS 的 @font-face 中找到字体文件 URL

# 2. 解析字体映射关系
font = TTFont("custom.woff")
cmap = font.getBestCmap()  # 获取字符映射表
print(cmap)  # 如 {97: 'uniE123', 98: 'uniE456'}

# 3. 根据映射表还原真实字符
def decode_text(encoded_text, mapping):
    # mapping = {'uniE123': '0', 'uniE456': '1', ...}
    result = ""
    for char in encoded_text:
        unicode_code = hex(ord(char))
        if unicode_code in mapping:
            result += mapping[unicode_code]
        else:
            result += char
    return result
```

## 39. 布隆过滤器（Bloom Filter）在爬虫去重中如何应用？

**精简回答**：布隆过滤器是一种空间效率极高的概率型数据结构，用少量的内存表示大量数据，但存在一定的误判率（可能将未访问过的 URL 误判为已访问）。

```python
import redis
import hashlib

class BloomFilter:
    def __init__(self, redis_client, key='bloom', bit_size=1 << 27, hash_count=6):
        self.redis = redis_client
        self.key = key
        self.bit_size = bit_size
        self.hash_count = hash_count

    def _hashes(self, value):
        """生成多个哈希值"""
        md5 = hashlib.md5(value.encode()).hexdigest()
        sha1 = hashlib.sha1(value.encode()).hexdigest()
        return [(int(md5[i:i+8], 16) % self.bit_size,
                 int(sha1[i:i+8], 16) % self.bit_size) for i in range(0, 32, 8)]

    def add(self, value):
        for h1, h2 in self._hashes(value):
            self.redis.setbit(self.key, h1, 1)
            self.redis.setbit(self.key, h2, 1)

    def contains(self, value):
        for h1, h2 in self._hashes(value):
            if not self.redis.getbit(self.key, h1) or not self.redis.getbit(self.key, h2):
                return False
        return True

# 使用布隆过滤器可以极大节省内存
# 1 亿个 URL，集合存储需要 ~10GB 内存，布隆过滤器只需要 ~120MB
```

# 十三、爬虫的法律与合规

## 41. 爬虫有哪些法律风险？如何合法合规地做爬虫？

**精简回答**：面试官非常看重候选人的法律意识，这个问题必须认真准备。

**法律风险**：

| 违法行为               | 风险说明                 |
| ---------------------- | ------------------------ |
| 侵入计算机信息系统     | 绕过身份验证、越权访问   |
| 获取商业秘密           | 爬取非公开的商业数据     |
| 侵犯公民个人信息       | 非法获取手机号、身份证等 |
| 破坏计算机系统         | 高频请求导致网站瘫痪     |
| 违反《反不正当竞争法》 | 抓取竞品数据进行商业使用 |

**合法合规建议**：
1. **遵守 robots.txt**：这是网站与爬虫之间的“君子协定”
2. **控制请求频率**：设置合理的访问间隔，不对服务器造成负担
3. **仅爬取公开数据**：不绕过登录验证获取非公开信息
4. **不抓取敏感信息**：如个人隐私数据、商业机密
5. **遵守网站服务条款**：仔细阅读 API 使用协议
6. **数据用途合规**：不用于损害原网站的商业竞争

```python
import urllib.robotparser

def check_robots(url):
    rp = urllib.robotparser.RobotFileParser()
    rp.set_url("https://example.com/robots.txt")
    rp.read()
    if rp.can_fetch("*", url):
        print(f"可以爬取 {url}")
    else:
        print(f"robots.txt 禁止爬取 {url}")
```

> 爬虫技术的最终目的是为了更好地服务用户，促进社会信息的流通与共享，而非滥用技术侵犯他人权益。
