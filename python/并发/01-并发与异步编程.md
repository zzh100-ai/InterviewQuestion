### 1. 并行与并发有什么区别？

**精简回答**：  

- **并发**：多个任务在同一时间段内交替执行（单核 CPU 时间片轮转），适合 I/O 密集型任务。  
- **并行**：多个任务在同一时刻真正同时执行（多核 CPU），适合 CPU 密集型任务。  
Python 多线程由于 GIL，无法实现真正的并行（只能并发），并行需要用多进程。

**原理展开**：  
```text
并发（Concurrency）：
    Thread A ──┐
    Thread B ──┼── 交替使用 CPU
    Thread C ──┘

并行（Parallelism）：
    Core 1: Thread A ──────────
    Core 2: Thread B ──────────
```

**生活例子**：  
- 并发：一个食堂阿姨，轮流给三个人打饭。  
- 并行：三个阿姨同时给三个人打饭。

### 2. 说说进程、线程和协程的区别？

**精简回答**：  
| 项目        | 进程              | 线程         | 协程                     |
| ----------- | ----------------- | ------------ | ------------------------ |
| 资源分配    | 独立内存空间      | 共享进程内存 | 共享线程内存             |
| 切换开销    | 大（内核态）      | 中（内核态） | 极小（用户态）           |
| 调度方式    | 操作系统          | 操作系统     | 程序自身（事件循环）     |
| Python 实现 | `multiprocessing` | `threading`  | `asyncio`                |
| 适用场景    | CPU 密集型        | I/O 密集型   | 高并发 I/O（如网络请求） |

**GIL 影响**：  
- 多线程只能并发（不能并行），适合 I/O 密集型。  
- 多进程可以并行，但创建开销大。

**代码示例**：  
```python
# 进程
from multiprocessing import Process
p = Process(target=func)

# 线程
from threading import Thread
t = Thread(target=func)

# 协程
import asyncio
async def func(): ...
asyncio.run(func())
```

### 3. Python 中创建线程有几种方式？

**精简回答**：三种  
1. 直接使用 `threading.Thread(target=func)`  
2. 继承 `threading.Thread` 并重写 `run()`  
3. 使用 `concurrent.futures.ThreadPoolExecutor`

**代码示例**：  
```python
# 方式1
def task():
    print("Thread running")
t = threading.Thread(target=task)
t.start()

# 方式2
class MyThread(threading.Thread):
    def run(self):
        print("Thread running")
t = MyThread()
t.start()

# 方式3
from concurrent.futures import ThreadPoolExecutor
with ThreadPoolExecutor() as executor:
    executor.submit(task)
```

### 4. 调用 start() 和直接调用 run() 有什么区别？

- `start()`：启动一个新线程，在新线程中执行 `run()` 方法。  
- 直接调用 `run()`：在当前线程中同步执行，不会创建新线程。

```python
t = threading.Thread(target=print, args=("Hello",))
t.start()   # 新线程
t.run()     # 主线程执行
```

### 5. Python 线程有哪些常用调度方法？

| 方法                            | 说明                         |
| ------------------------------- | ---------------------------- |
| `start()`                       | 启动线程                     |
| `join(timeout=None)`            | 等待线程结束                 |
| `sleep(sec)`                    | 当前线程休眠（`time.sleep`） |
| `Lock.acquire()` / `release()`  | 获取/释放锁                  |
| `Event.wait()` / `set()`        | 等待/通知                    |
| `Condition.wait()` / `notify()` | 条件变量                     |

> 基础控制调度：`join()` 与 `sleep()`

通过 `time.sleep()` 促使当前线程释放 CPU，以及使用 `Thread.join()` 阻塞主线程直到子线程结束，是最简单、最直观的线程调度方式。

```python
import threading
import time

def task(name, duration):
    print(f"线程 {name} 开始执行...")
    # 模拟 I/O 阻塞，主动让出 CPU
    time.sleep(duration)
    print(f"线程 {name} 执行结束。")

# 创建两个线程
t1 = threading.Thread(target=task, args=("A", 2))
t2 = threading.Thread(target=task, args=("B", 1))

t1.start()
# 调度控制：等 t1 执行完毕后，再启动 t2
t1.join() 

t2.start()
t2.join()

print("所有线程调度完毕。")
```
* **适用场景**：适合简单的顺序执行，或者需要严格等待上一个线程完成才能开始下一步的场景。

> 基于信号的事件调度：`threading.Event`

`threading.Event` 是一种简单的线程间通信机制。一个线程可以通过设置或清除信号，来调度和控制其他处于等待状态的线程。

```python
import threading
import time

# 初始化事件对象
ready_event = threading.Event()

def worker():
    print("工作线程已启动，等待数据初始化完成...")
    # 阻塞，直到 ready_event 被设置 (set)
    ready_event.wait()
    print("收到初始化完成信号，开始处理核心业务。")

def initializer():
    print("初始化线程：正在加载资源...")
    time.sleep(2)
    print("初始化线程：资源加载完成。")
    # 发送信号，唤醒所有在等待该事件的线程
    ready_event.set()

t_worker = threading.Thread(target=worker)
t_init = threading.Thread(target=initializer)

t_worker.start()
t_init.start()

t_worker.join()
t_init.join()
```
* **适用场景**：一/多线程需要等待某个单一的前置条件（如初始化、配置文件加载、连接建立）完成后再统一开始运行。

> 条件变量调度：`threading.Condition`

当复杂的调度逻辑依赖于某个特定的“状态”时，可以使用 `threading.Condition`（条件变量）。它允许线程在未满足条件时挂起，并在条件满足时通过 `notify()` 或 `notify_all()` 被唤醒。

```python
import threading
import time

condition = threading.Condition()
items = []

def consumer():
    with condition:
        while not items:
            print("消费者：队列为空，等待生产者生成数据...")
            # wait() 会释放持有的锁，并挂起线程，直到被 notify 唤醒并重新获取锁
            condition.wait()
        item = items.pop(0)
        print(f"消费者：成功消费数据 -> {item}")

def producer():
    time.sleep(1.5)
    with condition:
        items.append("数据包_A")
        print("生产者：生产了 数据包_A，正在通知消费者...")
        # 唤醒正在等待该条件的线程
        condition.notify()

t_cons = threading.Thread(target=consumer)
t_prod = threading.Thread(target=producer)

t_cons.start()
t_prod.start()

t_cons.join()
t_prod.join()
```
* **适用场景**：线程的调度依赖于多变共享资源的状态（如缓冲区空/满、计数器达到特定值）。

> 任务优先级调度：`queue.PriorityQueue`

如果需要让多个工作线程优先处理重要的任务，可以使用线程安全的 `queue.PriorityQueue`。虽然这并非直接调度线程本身，但它能间接实现“高优先级任务先调度，低优先级任务后调度”。

```python
import threading
import queue
import time

# 创建优先级队列
task_queue = queue.PriorityQueue()

def worker(worker_id):
    while not task_queue.empty():
        try:
            # 优先级队列中，元组的第一个元素越小，优先级越高
            priority, task_name = task_queue.get(timeout=1)
            print(f"工作线程 {worker_id} 正在执行: {task_name} (优先级: {priority})")
            time.sleep(0.5)
            task_queue.task_done()
        except queue.Empty:
            break

# 放入不同优先级的任务 (数值越小优先级越高)
task_queue.put((3, "发送日常报告"))
task_queue.put((1, "处理服务器宕机告警"))
task_queue.put((2, "备份数据库"))

# 启动工作线程执行调度
threads = []
for i in range(2):
    t = threading.Thread(target=worker, args=(i+1,))
    threads.append(t)
    t.start()

for t in threads:
    t.join()
```
* **适用场景**：任务有明确的轻重缓急之分（如应急响应、消息队列消费等）。

> 定时/延时调度：`threading.Timer`

`threading.Timer` 是 `Thread` 的子类，用于在指定的延迟时间之后，在独立的线程中执行某个函数。

#### 示例代码：
```python
import threading

def delayed_task():
    print("延迟任务：定时时间到，执行成功！")

print("主线程：创建定时器，设定 3.0 秒后执行任务...")
timer = threading.Timer(3.0, delayed_task)

timer.start() # 启动定时器线程

# 可以在尚未触发之前调用 timer.cancel() 取消调度
# timer.cancel()

timer.join()
print("主线程结束。")
```
* **适用场景**：延时重试、简单的定时心跳发送、超时保护等。

> 高级线程池调度：`concurrent.futures.ThreadPoolExecutor`

当需要处理大量任务并控制最大并发数时，直接管理 `threading.Thread` 的生命周期非常繁琐。推荐使用 Python 3 标准库提供的 `ThreadPoolExecutor`。

```python
from concurrent.futures import ThreadPoolExecutor, as_completed
import time

def process_data(data):
    time.sleep(0.5)
    return f"数据 {data} 处理完成"

dataset = [10, 20, 30, 40, 50]

# 限制最大并发线程数为 3
with ThreadPoolExecutor(max_workers=3) as executor:
    # 调度提交任务，返回 future 对象
    futures = {executor.submit(process_data, data): data for data in dataset}
    
    # 按照任务完成的先后顺序获取结果（非提交顺序）
    for future in as_completed(futures):
        data = futures[future]
        try:
            result = future.result()
            print(f"调度反馈: {result}")
        except Exception as exc:
            print(f"任务 {data} 运行出错: {exc}")
```
* **适用场景**：多任务并发控制、高吞吐的爬虫或 I/O 密集型接口调用。

### 6. Python 线程有几种状态？

Python 线程状态与 Java 类似，可通过 `threading.enumerate()` 查看。

| 状态     | 说明                                |
| -------- | ----------------------------------- |
| **新建** | `Thread` 对象创建，未调用 `start()` |
| **就绪** | 调用 `start()`，等待 CPU 调度       |
| **运行** | 获得 GIL 并执行                     |
| **阻塞** | 等待锁、I/O、`sleep` 等             |
| **终止** | `run()` 执行完毕或抛出未捕获异常    |

**如何强制终止线程？**  
Python 没有 `stop()` 方法，推荐使用 `Event` 标志：
```python
stop_event = threading.Event()
def task():
    while not stop_event.is_set():
        # 工作
        pass
# 终止
stop_event.set()
```

### 7. 什么是线程上下文切换？

线程上下文切换指 CPU 从一个线程切换到另一个线程时，保存当前线程的状态（寄存器、程序计数器等），加载新线程的状态。

Python 中 GIL 导致即使是多核 CPU，同一时刻也只有一个线程执行 Python 字节码。线程切换发生在：
- 时间片用完
- I/O 阻塞
- 显式释放 GIL（如调用 C 扩展）

**多核调度**：  
- 多核 CPU 上，不同核心可以同时执行不同进程。  
- 对于线程，由于 GIL，多个线程无法真正并行，但线程仍可在不同核心间切换。

### 8. 守护线程了解吗？

**定义**：守护线程（Daemon Thread）是为其他线程提供服务的线程，如垃圾回收、心跳检测。

**特点**：  
- 当所有非守护线程结束时，守护线程会自动终止（无论是否执行完毕）。  
- 设置方法：`thread.daemon = True`（必须在 `start()` 前设置）。

```python
import threading
import time

def daemon_task():
    while True:
        print("Daemon running")
        time.sleep(1)

d = threading.Thread(target=daemon_task, daemon=True)
d.start()
time.sleep(3)   # 主线程结束，守护线程退出
```

### 9. 线程间有哪些通信方式？

| 方式     | 说明               | Python 实现                        |
| -------- | ------------------ | ---------------------------------- |
| 共享变量 | 使用锁保护         | `Lock` + 普通变量                  |
| 队列     | 线程安全的数据交换 | `queue.Queue`                      |
| 条件变量 | 等待/通知          | `threading.Condition`              |
| 事件     | 信号通知           | `threading.Event`                  |
| 管道     | 单向/双向通信      | `multiprocessing.Pipe`（用于进程） |

> 共享变量（`Lock` + 普通变量）

由于多线程共享相同的内存空间，它们可以直接读写同一个全局变量。但是，为了避免产生数据竞争（Race Condition），必须使用 `threading.Lock` 保护修改操作。

```python
import threading

# 共享变量
counter = 0
# 互斥锁，用于保护共享变量
lock = threading.Lock()

def increment():
    global counter
    for _ in range(100000):
        # 使用 with 语句自动获取和释放锁
        with lock:
            counter += 1

# 创建两个线程同时对 counter 进行累加
t1 = threading.Thread(target=increment)
t2 = threading.Thread(target=increment)

t1.start()
t2.start()
t1.join()
t2.join()

print(f"最终 Counter 结果: {counter} (预期值: 200000)")
```

> 队列（`queue.Queue`）

`queue.Queue` 是 Python 标准库中提供的**线程安全**的双端队列。由于其内部已经封装了锁和条件变量，因此开发者无需手动加锁，是多线程数据交换的首选方式。

```python
import threading
import queue
import time

# 创建一个线程安全的队列
msg_queue = queue.Queue()

def producer():
    for i in range(3):
        msg = f"消息_{i}"
        msg_queue.put(msg)  # 放入队列
        print(f"【生产者】放入了: {msg}")
        time.sleep(0.5)

def consumer():
    while True:
        # get() 在队列为空时会默认阻塞，直到获取到数据
        msg = msg_queue.get()
        if msg is None:  # 收到结束标记，退出循环
            break
        print(f"【消费者】消费了: {msg}")
        msg_queue.task_done()

t_prod = threading.Thread(target=producer)
t_cons = threading.Thread(target=consumer)

t_prod.start()
t_cons.start()

t_prod.join()
msg_queue.put(None)  # 发送结束标记（哨兵）通知消费者退出
t_cons.join()
```

> 条件变量（`threading.Condition`）

条件变量用于在某个特定“条件”满足时唤醒其他线程。通常包含一个关联的锁，线程通过 `wait()` 释放锁并进入等待状态，另一个线程在修改状态后通过 `notify()` 通知等待的线程重新获取锁并继续执行。

```python
import threading
import time

cond = threading.Condition()
product_box = []  # 共享资源

def receiver():
    with cond:
        # 如果产品箱为空，则持续等待
        while not product_box:
            print("【接收端】产品箱为空，等待中...")
            cond.wait()  # 释放锁并挂起线程，等待被唤醒
        print(f"【接收端】成功拿到产品: {product_box.pop()}")

def sender():
    time.sleep(1.5)  # 模拟生产耗时
    with cond:
        product_box.append("智能芯片")
        print("【发送端】产品已放入箱内，正在发出通知...")
        cond.notify()  # 唤醒正在等待该条件的线程

t_rec = threading.Thread(target=receiver)
t_send = threading.Thread(target=sender)

t_rec.start()
t_send.start()
t_rec.join()
t_send.join()
```

> 事件（`threading.Event`）

`threading.Event` 用于线程间的状态标记和信号通知。它的状态只有“已设置 (set)”和“未设置 (clear)”两种。一个或多个线程可以通过调用 `wait()` 处于阻塞状态，直到另一个线程调用 `set()` 发出信号。

```python
import threading
import time

# 初始化事件，默认状态为 False (未设置)
start_signal = threading.Event()

def worker(name):
    print(f"线程 {name} 准备就绪，等待主线程发射信号...")
    start_signal.wait()  # 阻塞，直到事件被设为 True
    print(f"线程 {name} 收到信号，开始全速运行！")

# 创建多个等待信号的线程
t1 = threading.Thread(target=worker, args=("A",))
t2 = threading.Thread(target=worker, args=("B",))
t1.start()
t2.start()

time.sleep(2)
print("【主线程】准备完毕，发送开始信号！")
start_signal.set()  # 唤醒所有等待该事件的线程

t1.join()
t2.join()
```

> 管道（`multiprocessing.Pipe`）

`multiprocessing.Pipe` 主要是为多**进程**通信设计的，但由于它返回的双端连接对象（Connection）在底层也是通过系统级的套接字或管道实现的，因此它也**完全可以用于线程间通信**。

> **注意：** 线程间共享内存，通常首选 `queue.Queue` 或共享变量。使用 `Pipe` 会产生额外的序列化/反序列化（Pickle）开销，一般仅在需要保持与进程通信代码结构一致时，才在线程中使用。

```python
from multiprocessing import Pipe
import threading
import time

# Pipe() 返回一对连接对象 (conn1, conn2)，分别代表管道的两端
parent_conn, child_conn = Pipe()

def sender_thread(conn):
    print("【管道发送端】正在准备数据...")
    time.sleep(1)
    data = {"id": 101, "payload": "线程安全测试数据"}
    conn.send(data)  # 发送数据
    print("【管道发送端】数据已发送。")
    conn.close()

def receiver_thread(conn):
    print("【管道接收端】等待接收数据...")
    data = conn.recv()  # 阻塞接收，直到收到数据
    print(f"【管道接收端】成功收到数据: {data}")
    conn.close()

# 创建线程，分别持有管道的两端
t1 = threading.Thread(target=sender_thread, args=(child_conn,))
t2 = threading.Thread(target=receiver_thread, args=(parent_conn,))

t1.start()
t2.start()
t1.join()
t2.join()
```

### 11. 怎么保证线程安全？

**精简回答**：  

1. 使用 `threading.Lock` 或 `RLock` 对临界区加锁。  
2. 使用 `queue.Queue` 等线程安全容器。  
3. 使用 `threading.local()` 实现线程本地变量。  
4. 使用不可变对象（如字符串、元组）。  
5. 对于原子操作（如列表的 `append`），大部分是线程安全的（但并非全部）。

**示例：计数器问题**  
```python
import threading
counter = 0
lock = threading.Lock()

def increment():
    global counter
    for _ in range(10000):
        with lock:
            counter += 1

# 10个线程结果应为100000，无锁结果小于100000
```

**使用 `threading.local`**：
```python
local_data = threading.local()
local_data.user = "admin"   # 每个线程独立副本
```

### 12. `threading.local` 是什么？

**定义**：`threading.local` 为每个线程提供独立的变量副本，实现线程隔离。

**使用场景**：  
- Web 请求中存储用户信息（避免参数层层传递）  
- 数据库连接（每个线程一个连接）  
- 日志上下文

**示例**：
```python
import threading
local = threading.local()

def worker():
    local.val = 42
    print(local.val)

t1 = threading.Thread(target=worker)
t2 = threading.Thread(target=worker)
t1.start(); t2.start()
```

**原理**：每个线程内部维护一个字典 `__dict__`，key 为 `local` 对象，value 为线程私有数据。

**内存泄漏问题**：  

- 如果线程长期存活（如线程池），且未清理 `local` 变量，可能导致内存泄漏。  
- 解决办法：使用完后 `del local.val` 或调用 `local.__dict__.clear()`。

---

### 13. 父线程能通过 `threading.local` 给子线程传值吗？

**不能**。`threading.local` 的数据是线程隔离的，子线程无法继承父线程的 `local` 数据。  
如果要传递，可以使用 `threading.local` 的子类 `threading.local` 本身不支持继承，或者显式传递参数。

**替代方案**：使用 `contextvars` 模块（Python 3.7+）：

```python
from contextvars import ContextVar
var = ContextVar('var', default=None)
var.set("parent")
# 子线程中可通过 var.get() 获取
```

## Python 内存模型与 GIL

### 14. 说一下 Python 的内存模型？

Python 没有像 Java 那样的严格 JMM，但存在类似概念：  
- **主内存**：所有变量存储位置（实际是操作系统内存）  
- **工作内存**：线程本地缓存（CPython 中通过 GIL 简化）  

由于 GIL 的存在，**简单变量的读写操作是原子的**（因为 GIL 保证同一时刻只有一个线程执行字节码），但复合操作（如 `count += 1`）仍需要锁。

**可见性**：  

- 一个线程修改变量后，其他线程不一定立即看到，因为 CPU 缓存可能未刷新。  
- 解决方法：使用 `Lock` 或 `threading.Event` 强制同步。

---

### 15. `count += 1` 是原子操作吗？

**在 Python 中，`count += 1` 不是原子操作**，尽管 GIL 保证了单条字节码的原子性，但 `+=` 会编译为多条字节码：
```
LOAD_FAST   count
LOAD_CONST  1
INPLACE_ADD
STORE_FAST  count
```
因此多个线程同时执行可能导致结果丢失。**必须加锁**。

---

### 16. 说说 Python 的 GIL 是什么？

**GIL（全局解释器锁）** 是 CPython 中的一个互斥锁，保证同一时刻只有一个线程执行 Python 字节码。

**优点**：  

- 简化了 CPython 的内存管理（引用计数无需复杂锁）。  
- 单线程性能较好。

**缺点**：  
- 多线程无法利用多核 CPU 进行并行计算。  
- CPU 密集型任务使用多线程反而更慢（因为锁竞争）。

**如何绕过 GIL**：  
1. 使用多进程（`multiprocessing`）。  
2. 使用 C 扩展（如 `numpy`），在 C 层面释放 GIL。  
3. 使用异步 I/O（`asyncio`）进行并发。

**GIL 与 I/O 操作**：  
当线程执行 I/O 操作（如 `socket.read`）时，会释放 GIL，因此多线程依然适合 I/O 密集型任务。

---

### 17. 什么是指令重排？Python 会有这个问题吗？

指令重排是 CPU/编译器为了优化性能，改变代码执行顺序的现象。

Python 字节码层面**不会发生重排**（因为是解释执行）。但底层 C 代码编译时可能重排，不过由于 GIL 的存在，多线程看到的内存操作顺序相对简单。  
实际开发中，Python 程序极少遇到指令重排问题，不需要像 Java 那样使用 `volatile`。

---

### 18. 聊聊 `as-if-serial` 语义？

在单线程中，无论怎样重排序，执行结果必须和代码顺序一致。  
Python 解释器遵循该规则，所以单线程代码安全。多线程仍需锁。

## 锁与同步

### 19. `threading.Lock` 用过吗？

**常用锁**：

- `Lock`：互斥锁，不可重入  
- `RLock`：可重入锁（同一个线程可以多次 acquire）  
- `Semaphore`：信号量（限制并发数）  
- `Event`：事件通知  
- `Condition`：条件变量（可以 wait/notify）

**示例**：
```python
import threading
lock = threading.Lock()
def func():
    with lock:
        # 临界区
        pass
```

---

### 20. `Lock` 与 `RLock` 的区别？

| 特性     | `Lock`                            | `RLock`                                  |
| -------- | --------------------------------- | ---------------------------------------- |
| 可重入性 | 否（同一线程再次 acquire 会死锁） | 是（可多次 acquire，需相同次数 release） |
| 所有者   | 无                                | 记录持有线程                             |
| 性能     | 略高                              | 略低                                     |

**RLock 示例**：
```python
rlock = threading.RLock()
rlock.acquire()
rlock.acquire()   # 允许
rlock.release()
rlock.release()
```

---

### 21. 说说 `Condition` 的使用？

`Condition` 提供 `wait()`、`notify()` 方法，通常配合锁使用。

**生产者-消费者示例**：
```python
import threading

cv = threading.Condition()
items = []

def producer():
    with cv:
        items.append("item")
        cv.notify()

def consumer():
    with cv:
        while not items:
            cv.wait()
        item = items.pop()
```

---

### 22. 死锁是什么？如何避免？

**死锁**：两个或多个线程互相等待对方释放锁，导致程序永久阻塞。

**四个必要条件**：  
1. 互斥  
2. 持有并等待  
3. 不可抢占  
4. 循环等待

**避免方法**：  
- 按固定顺序获取锁  
- 使用 `acquire(timeout=...)` 超时放弃  
- 使用 `threading.RLock` 减少错误  
- 尽量使用更高级的抽象（如 `queue.Queue`）

---

### 23. 什么是乐观锁和悲观锁？

| 类型   | 思路                 | Python 实现                                              |
| ------ | -------------------- | -------------------------------------------------------- |
| 悲观锁 | 每次访问数据都加锁   | `Lock`、`RLock`                                          |
| 乐观锁 | 更新时检查是否被修改 | 无内置，可使用版本号或 CAS（通过 `ctypes` 调用原子操作） |

Python 中常用悲观锁。乐观锁可以通过 `multiprocessing.Value` 的 `get_lock()` 实现，但本质还是锁。

## 并发工具类

### 24. `queue.Queue` 了解吗？

`Queue` 是线程安全的 FIFO 队列，内部使用 `deque` + 锁实现。

**常用方法**：
- `put(item, block=True, timeout=None)`  
- `get(block=True, timeout=None)`  
- `task_done()` / `join()`（用于等待所有任务完成）

**示例**：
```python
from queue import Queue
import threading

q = Queue()
def worker():
    while True:
        item = q.get()
        if item is None:
            break
        # 处理 item
        q.task_done()

threading.Thread(target=worker, daemon=True).start()
for i in range(10):
    q.put(i)
q.join()        # 等待所有任务完成
```

---

### 25. `multiprocessing.Queue` 与 `queue.Queue` 区别？

| 对比     | `queue.Queue`    | `multiprocessing.Queue`     |
| -------- | ---------------- | --------------------------- |
| 适用范围 | 同一进程内多线程 | 多进程间通信                |
| 实现     | 基于线程锁       | 基于管道 + 序列化（pickle） |
| 性能     | 较快             | 较慢，因为跨进程            |

---

### 26. `threading.Event` 了解吗？

`Event` 类似一个标志位，用于线程间简单信号通知。

```python
event = threading.Event()
# 线程 A 等待
event.wait()
# 线程 B 设置
event.set()
```

可以用于线程启动同步、停止信号等。

---

### 27. `threading.Barrier` 了解吗？

`Barrier` 让多个线程相互等待，直到达到一定数量后才一起继续。

```python
barrier = threading.Barrier(3)
def task():
    print("waiting")
    barrier.wait()
    print("go")
# 启动 3 个线程，会同时打印 "go"
```

## 线程池与进程池

### 28. 什么是线程池/进程池？

线程池预先创建一组线程，重复利用，避免频繁创建销毁开销。  
Python 中推荐使用 `concurrent.futures` 模块。

**线程池**：

```python
from concurrent.futures import ThreadPoolExecutor
with ThreadPoolExecutor(max_workers=4) as executor:
    futures = [executor.submit(fn, arg) for arg in args]
```

**进程池**：
```python
with ProcessPoolExecutor(max_workers=4) as executor:
    ...
```

---

### 29. 线程池的核心参数有哪些？

`ThreadPoolExecutor` 主要参数：
- `max_workers`：最大工作线程数（默认 CPU 数 * 5）
- `thread_name_prefix`：线程名前缀
- `initializer` / `initargs`：初始化函数

**工作流程**：  
提交任务 → 如果有空闲线程，立即执行 → 否则任务进入队列等待 → 线程执行完一个任务后，从队列取下一个。

**拒绝策略**：  
Python 线程池队列默认无界，不会拒绝任务（可能导致内存爆炸）。可设置 `maxsize` 自定义队列，通过异常处理模拟拒绝。

---

### 30. `submit` 与 `map` 的区别？

- `submit(fn, *args)`：提交单个任务，返回 `Future` 对象。  
- `map(fn, *iterables)`：批量提交，返回迭代器，保持顺序。

```python
with ThreadPoolExecutor() as ex:
    future = ex.submit(pow, 2, 10)
    result = future.result()

    results = ex.map(str.upper, ['a','b','c'])
```

---

### 31. 如何关闭线程池？

- `shutdown(wait=True)`：等待所有任务完成后再关闭（类似 `join`）。  
- 使用上下文管理器 `with`，自动调用 `shutdown`。

```python
executor = ThreadPoolExecutor()
executor.submit(fn)
executor.shutdown(wait=True)
```

没有 `shutdownNow` 类似的方法（无法强制中断正在运行的任务），需要自己实现标志位。

---

### 32. 线程数应该怎么配置？

| 任务类型       | 建议线程数                              |
| -------------- | --------------------------------------- |
| CPU 密集型     | 不超过 CPU 核心数（通常 `cpu_count()`） |
| I/O 密集型     | 可以大一些，如 2~4 倍 CPU 核心数        |
| 高延迟网络请求 | 可设 50~200（但受限于系统资源）         |

**计算公式**（参考）：
```
最优线程数 = CPU 核心数 * (1 + 等待时间/计算时间)
```
但实际需要压测调整。

**如何判断过多/过少**：  
- 过多：CPU 上下文切换显著增加（`vmstat` 查看 `cs`），响应变慢  
- 过少：CPU 利用率低，任务堆积

---

### 33. 常见内置线程池有哪些问题？

使用 `ThreadPoolExecutor` 默认配置时注意：
- 队列无界，任务过多可能导致 OOM  
- 无法动态调整线程数（Python 3.9+ 可通过 `max_workers` 属性调整，但官方不推荐）  
- 异常默认不会抛出，需要使用 `future.result()` 获取

**自定义线程池**：
```python
from concurrent.futures import ThreadPoolExecutor
from queue import Queue

class BoundedThreadPoolExecutor(ThreadPoolExecutor):
    def __init__(self, max_workers, max_queue_size):
        self._work_queue = Queue(maxsize=max_queue_size)
        super().__init__(max_workers, thread_name_prefix='Bounded')
```

---

### 34. 线程池异常处理

```python
# 方式1：捕获 Future 异常
future = executor.submit(func)
try:
    result = future.result()
except Exception as e:
    print(e)

# 方式2：自定义 Future 回调
def handle(f):
    if f.exception():
        print(f.exception())
future.add_done_callback(handle)
```

## 协程与异步 IO

### 35. 协程是什么？与线程的区别？

**协程**：用户态的轻量级线程，由程序自己调度（事件循环），切换开销极小。

**对比**：
| 特性     | 线程           | 协程                                   |
| -------- | -------------- | -------------------------------------- |
| 调度方式 | 操作系统抢占式 | 程序协作式（await 点切换）             |
| 内存占用 | 约 8MB 栈      | 约 1KB 栈                              |
| 并发数量 | 数千           | 数十万                                 |
| 适用场景 | I/O 密集型     | 极高并发 I/O（如网络爬虫、Web 服务器） |

---

### 36. Python 中如何实现协程？

通过 `async/await` 语法和 `asyncio` 库。

```python
import asyncio

async def say_hello():
    print("Hello")
    await asyncio.sleep(1)
    print("World")

asyncio.run(say_hello())
```

**并发运行多个协程**：
```python
async def main():
    await asyncio.gather(
        say_hello(),
        say_hello()
    )
```

---

### 37. `await` 的作用是什么？

`await` 挂起当前协程，让出控制权给事件循环，直到被等待的协程或 Future 完成。  
类似 `yield from`，但语义更清晰。

---

### 38. 事件循环（Event Loop）是什么？

事件循环是协程的调度器，负责：
- 管理可等待对象（Task、Future）  
- 当遇到 `await` 时，切换到其他就绪协程  
- 监听 I/O 事件（如 socket 可读）

**示例**：
```python
loop = asyncio.get_event_loop()
loop.run_until_complete(main())
loop.close()
```

---

### 39. `asyncio.Queue` 如何使用？

异步队列，用于协程间安全交换数据。

```python
import asyncio

async def producer(q):
    for i in range(5):
        await q.put(i)
        await asyncio.sleep(0.1)

async def consumer(q):
    while True:
        item = await q.get()
        print(item)
        q.task_done()

async def main():
    q = asyncio.Queue()
    prod = asyncio.create_task(producer(q))
    cons = asyncio.create_task(consumer(q))
    await prod
    await q.join()
    cons.cancel()
```

---

### 40. 如何在协程中调用同步阻塞代码？

使用 `loop.run_in_executor` 将阻塞操作放到线程池或进程池中执行。

```python
import asyncio
import time

def blocking_io():
    time.sleep(2)
    return "done"

async def main():
    loop = asyncio.get_running_loop()
    result = await loop.run_in_executor(None, blocking_io)
    print(result)
```

---

### 41. 协程与多线程如何选择？

| 场景                         | 推荐方案        |
| ---------------------------- | --------------- |
| CPU 密集型计算               | 多进程          |
| 普通 I/O（文件、数据库）     | 多线程          |
| 超高并发网络 I/O（万级连接） | 协程（asyncio） |
| 混合型（计算+ I/O）          | 多进程 + 协程   |

## 多进程

### 42. 为什么需要多进程？

绕过 GIL，利用多核 CPU 进行并行计算。

```python
from multiprocessing import Process, cpu_count

def square(n):
    return n*n

if __name__ == "__main__":
    pool = Pool(processes=cpu_count())
    results = pool.map(square, range(100))
```

---

### 43. 进程间如何共享数据？

| 方式                              | 说明                                         |
| --------------------------------- | -------------------------------------------- |
| `multiprocessing.Value` / `Array` | 共享内存，可加锁                             |
| `multiprocessing.Queue`           | 队列（基于管道）                             |
| `multiprocessing.Pipe`            | 双向管道                                     |
| `multiprocessing.Manager`         | 代理对象，支持 `dict`、`list` 等，但性能较低 |

**示例**：
```python
from multiprocessing import Process, Value

def add(val):
    val.value += 1

if __name__ == "__main__":
    v = Value('i', 0)
    p = Process(target=add, args=(v,))
    p.start()
    p.join()
    print(v.value)
```

---

### 44. 进程池 `Pool` 的使用？

```python
from multiprocessing import Pool

def f(x):
    return x*x

if __name__ == "__main__":
    with Pool(processes=4) as pool:
        print(pool.map(f, range(10)))       # 阻塞
        print(pool.apply_async(f, (10,)).get())  # 异步
```

### 45. 守护进程？

- 设置 `p.daemon = True`，主进程结束时，守护进程自动终止。  
- 必须 `start()` 前设置。

## 手写代码题

### 46. 手写一个线程安全的单例模式

```python
import threading

class Singleton:
    _instance = None
    _lock = threading.Lock()

    def __new__(cls):
        if cls._instance is None:
            with cls._lock:
                if cls._instance is None:
                    cls._instance = super().__new__(cls)
        return cls._instance
```

### 47. 手写一个简单的线程池

```python
import threading
from queue import Queue

class ThreadPool:
    def __init__(self, num_threads):
        self.tasks = Queue()
        self.threads = []
        for _ in range(num_threads):
            t = threading.Thread(target=self._worker)
            t.daemon = True
            t.start()
            self.threads.append(t)

    def _worker(self):
        while True:
            func, args, kwargs = self.tasks.get()
            try:
                func(*args, **kwargs)
            except Exception:
                pass
            finally:
                self.tasks.task_done()

    def submit(self, func, *args, **kwargs):
        self.tasks.put((func, args, kwargs))

    def join(self):
        self.tasks.join()
```

### 48. 手写一个数据库连接池（Python）

```python
import threading
from queue import Queue
import sqlite3

class ConnectionPool:
    def __init__(self, db_path, max_connections=10):
        self.db_path = db_path
        self.pool = Queue(maxsize=max_connections)
        for _ in range(max_connections):
            conn = sqlite3.connect(db_path)
            self.pool.put(conn)

    def get_connection(self, timeout=None):
        return self.pool.get(timeout=timeout)

    def release_connection(self, conn):
        self.pool.put(conn)

    def close_all(self):
        while not self.pool.empty():
            conn = self.pool.get()
            conn.close()
```
