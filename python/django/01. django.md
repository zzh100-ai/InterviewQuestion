# 一、基础概念类

## 1. Django 是什么？它的核心特点有哪些？

**精简回答**：Django 是一个用 Python 编写的高级 Web 框架，遵循 **"Don't Repeat Yourself"（DRY）** 原则，鼓励快速开发和简洁实用的设计。核心特点包括：

- **电池已内置**：自带认证系统、ORM、管理后台、表单验证等，开箱即用
- **强大的 ORM**：通过面向对象方式操作数据库，无需手写 SQL
- **自动管理后台**：根据模型自动生成后台管理界面
- **完善的安全防护**：内置防止 SQL 注入、XSS、CSRF 等常见攻击的机制
- **URL 路由系统**：简洁的 URL 设计，支持正则表达式和路径转换器
- **可扩展性**：支持大型应用，Instagram 和 Pinterest 等公司都使用 Django

**原理展开**：Django 的"电池已内置"哲学意味着它提供了 Web 开发所需的大部分功能，无需开发者从零搭建技术栈。这种设计能够显著缩短项目启动时间，让团队专注于业务逻辑开发，同时也保证了代码的一致性和安全性。

## 2. 说说 Django 的 MVT 架构与 MVC 的区别？

**精简回答**：Django 采用的是 **MVT（Model-View-Template）** 架构，它是 MVC（Model-View-Controller）的一种变体。

| 组件       | MVC        | MVT      | 职责                               |
| ---------- | ---------- | -------- | ---------------------------------- |
| Model      | Model      | Model    | 数据层，定义数据结构，与数据库交互 |
| View       | View       | Template | 表现层，负责 HTML 页面渲染         |
| Controller | Controller | View     | 业务逻辑层，处理请求并返回响应     |

对应关系如下：
- **Model**：两边一致，负责数据存储和处理
- **View（MVC 中的 View）** → **Template（MVT 中的 Template）**：负责页面展示
- **Controller（MVC 中的 Controller）** → **View（MVT 中的 View）**：负责业务逻辑

路由配置（`urls.py`）在 MVT 中承担了部分 Controller 的转发职责。

## 3. Django 项目和 App 有什么区别？

**精简回答**：
- **Project（项目）**：整个网站的配置和应用的集合，是一个完整的 Web 项目
- **App（应用）**：完成特定功能的模块，如博客系统、用户认证系统等

一个项目可以包含多个应用，各应用之间相互独立，可以在不同项目中复用。用命令创建项目是 `django-admin startproject project_name`，创建应用是 `python manage.py startapp app_name`。

## 4. Django 如何处理请求生命周期？

**精简回答**：Django 的请求生命周期如下：

```
用户请求 → WSGI Server → 中间件（request 阶段）→ URL 路由 → 视图（View）→ 模板渲染（可选）→ 中间件（response 阶段）→ WSGI Server → 用户响应
```

**原理展开**：

1. 请求到达 WSGI 服务器（如 Gunicorn、uWSGI）
2. Django 将请求封装成 `HttpRequest` 对象
3. 依次执行 `MIDDLEWARE` 列表中的 `process_request` 方法
4. 通过 URLconf（`urls.py`）匹配路由，调用对应的视图
5. 视图执行业务逻辑（查询数据库、处理表单等）
6. 视图返回 `HttpResponse` 对象
7. 响应依次经过中间件的 `process_response` 方法
8. 最终返回给客户端

## 5. 说说 Django 和 Flask 的区别？什么时候选用 Django？

**精简回答**：

| 对比维度 | Django               | Flask                     |
| -------- | -------------------- | ------------------------- |
| 设计哲学 | 电池已内置，功能全面 | 微内核，按需扩展          |
| 适用场景 | 大型、复杂项目       | 小型、灵活、微服务        |
| ORM      | 内置强大 ORM         | 无内置，通常用 SQLAlchemy |
| 管理后台 | 自动生成             | 需自行开发                |
| 学习曲线 | 较陡                 | 平缓                      |
| 灵活性   | 较低（约定大于配置） | 较高                      |

**选择 Django 的场景**：
- 需要快速构建功能完整的大型项目
- 需要内置管理后台、ORM、用户认证等成熟方案
- 团队希望遵循 Django 的约定和最佳实践

**选择 Flask 的场景**：
- 需要极大灵活性，按需选择组件
- 构建微服务或小型 API 服务
- 项目规模较小，不希望引入过多依赖

# 二、Django ORM 与模型

## 6. Django 的 ORM 是什么？它有哪些优缺点？

**精简回答**：ORM（Object-Relational Mapping，对象关系映射）允许开发者使用 Python 类和对象来操作数据库，而无需手写 SQL。开发时，模型类自动映射到数据库表，Python 方法对应 SQL 操作。

**核心优势**：
- **抽象性**：无需深入掌握 SQL 即可操作数据库，支持跨数据库兼容（PostgreSQL、MySQL、SQLite 等）
- **安全性**：自动参数化查询，有效防止 SQL 注入攻击
- **便利性**：内置关系处理、数据验证和迁移管理
- **易维护**：数据模型集中定义，变更追踪清晰

**局限性**：

- 复杂查询（多表 JOIN、子查询）性能低于手写 SQL
- 某些数据库特定的高级功能（如全文搜索）支持有限
- 需要理解 ORM 的内部机制才能写出高效的查询

## 7. 什么是 QuerySet？它有哪些重要特性？

**精简回答**：QuerySet 是 Django ORM 中用于从数据库查询数据的对象集合。三个核心特性：

| 特性           | 说明                               | 示例                                                         |
| -------------- | ---------------------------------- | ------------------------------------------------------------ |
| **惰性执行**   | 只有在真正读取数据时才执行 SQL     | `books = Book.objects.filter(title__icontains="python")` 不会立即查询 |
| **可链式调用** | 可以连续调用过滤方法               | `Book.objects.filter(...).exclude(...).order_by(...)`        |
| **缓存机制**   | 同一 QuerySet 多次遍历不会重复查询 | 第二次遍历直接使用缓存结果                                   |

```python
# 惰性执行示例
books = Book.objects.filter(published=True)   # 不执行SQL
books = books.order_by('-created_at')         # 仍不执行SQL
for book in books:                            # 此时执行SQL
    print(book.title)                         # 后续遍历使用缓存，不再查询
```

## 8. 如何定义模型之间的关系？一对一、一对多、多对多？

**精简回答**：

| 关系类型 | Django 字段       | 使用场景               |
| -------- | ----------------- | ---------------------- |
| 一对多   | `ForeignKey`      | 作者和书籍、分类和文章 |
| 一对一   | `OneToOneField`   | 用户和用户资料         |
| 多对多   | `ManyToManyField` | 学生和课程、文章和标签 |

```python
from django.db import models

class Author(models.Model):
    name = models.CharField(max_length=100)

class Book(models.Model):
    title = models.CharField(max_length=200)
    author = models.ForeignKey(Author, on_delete=models.CASCADE, related_name='books')  # 一对多

class User(models.Model):
    username = models.CharField(max_length=50)

class Profile(models.Model):
    user = models.OneToOneField(User, on_delete=models.CASCADE)  # 一对一
    bio = models.TextField()

class Student(models.Model):
    name = models.CharField(max_length=100)

class Course(models.Model):
    name = models.CharField(max_length=100)
    students = models.ManyToManyField(Student, related_name='courses')  # 多对多
```

## 9. 什么是 N+1 查询问题？如何解决？

**精简回答**：N+1 查询是常见的性能问题：查询主表时获取 N 条记录，随后在循环中访问每条记录的外键关联，导致额外执行 N 次查询。

**症状**：列表接口响应时间从 80ms 飙升到 800ms，SQL 查询数量从 3 条暴增到 203 条。

**解决方案**：

| 方法                 | 适用场景                   | 原理                                           |
| -------------------- | -------------------------- | ---------------------------------------------- |
| `select_related()`   | 一对多（外键）、一对一     | 执行 SQL JOIN，一次性获取关联数据              |
| `prefetch_related()` | 多对多、一对多（反向查询） | 先查主表，再批量查询关联表，在 Python 层面合并 |

```python
# 错误示例：N+1 查询
books = Book.objects.all()           # 1次查询
for book in books:
    print(book.author.name)          # 每本书再查1次，共N+1次

# 正确示例：使用 select_related
books = Book.objects.select_related('author').all()  # 1次JOIN查询
for book in books:
    print(book.author.name)          # 已预加载，无额外查询

# 使用 prefetch_related（多对多场景）
courses = Course.objects.prefetch_related('students').all()  # 2次查询
```

> **加分项**：只取必要字段用 `only()`/`values()`；批量统计用 `annotate()`；开启日志监控慢查询。

## 10. 说说 Django 的信号（Signals）及其使用场景？

**精简回答**：信号是 Django 的事件通知机制，当某些动作发生时触发钩子函数，用于解耦不同模块间的逻辑。

**常见信号及使用场景**：

| 信号                         | 触发时机     | 典型用途                       |
| ---------------------------- | ------------ | ------------------------------ |
| `pre_save` / `post_save`     | 模型保存前后 | 自动生成 slug、发送通知        |
| `pre_delete` / `post_delete` | 模型删除前后 | 清理关联文件、记录日志         |
| `post_migrate`               | 数据库迁移后 | 初始化默认数据                 |
| `user_logged_in`             | 用户登录时   | 记录登录日志、更新最后登录时间 |

```python
from django.db.models.signals import post_save
from django.dispatch import receiver
from django.contrib.auth.models import User

@receiver(post_save, sender=User)
def create_user_profile(sender, instance, created, **kwargs):
    """用户注册后自动创建用户资料"""
    if created:
        Profile.objects.create(user=instance)
```

> **注意**：信号是同步执行的，不要放耗时操作。过度使用会让代码逻辑分散、难以追踪，简单场景建议直接调用。

## 11. 数据库迁移（Migration）的原理是什么？

**精简回答**：Django 迁移系统将模型变更（Python 代码）转换为数据库 Schema 变更。

**工作原理**：
1. `makemigrations`：对比当前模型和已有迁移文件，生成新的迁移文件（包含 `operations` 列表）
2. `migrate`：将未应用的迁移记录到 `django_migrations` 表，并执行对应的 SQL

```bash
python manage.py makemigrations    # 生成迁移文件
python manage.py migrate           # 应用到数据库
python manage.py showmigrations    # 查看迁移状态
python manage.py sqlmigrate app_name 0001   # 查看迁移对应的SQL
```

**常用迁移操作**：
- `AddField`：添加字段（可指定默认值）
- `RemoveField`：删除字段
- `AlterField`：修改字段属性
- `RunPython`：执行自定义 Python 代码进行数据迁移

## 12. Django 事务如何处理？

**精简回答**：Django 使用 `@transaction.atomic` 装饰器或上下文管理器来保证数据库操作的原子性。

```python
from django.db import transaction

# 方式1：装饰器
@transaction.atomic
def transfer_money(from_acc, to_acc, amount):
    from_acc.balance -= amount
    from_acc.save()
    to_acc.balance += amount
    to_acc.save()
    # 任何异常都会回滚

# 方式2：上下文管理器
def create_order_with_items(order_data, items):
    with transaction.atomic():
        order = Order.objects.create(**order_data)
        for item in items:
            OrderItem.objects.create(order=order, **item)
    return order

# 方式3：设置保存点（部分回滚）
with transaction.atomic():
    order = Order.objects.create(...)
    sid = transaction.savepoint()   # 创建保存点
    try:
        # 某些可能失败的操作
        payment = process_payment(...)
    except:
        transaction.savepoint_rollback(sid)   # 回滚到保存点
```

## 13. `F()` 表达式和 `Q()` 表达式有什么作用？

**精简回答**：

| 表达式 | 作用                                  | 典型场景             |
| ------ | ------------------------------------- | -------------------- |
| `F()`  | 引用模型字段的值，避免竞态条件        | 计数累加、字段间运算 |
| `Q()`  | 构建复杂的查询条件（AND/OR/NOT 组合） | 多条件搜索、动态过滤 |

```python
from django.db.models import F, Q

# F() 表达式：避免竞态条件 + 字段间运算
Article.objects.filter(id=1).update(views=F('views') + 1)   # 原子操作
Product.objects.filter(price__lt=F('cost'))                 # 价格低于成本的商品
Product.objects.update(total_price=F('price') * F('quantity'))

# Q() 对象：复杂查询
# 查找价格大于100且已发布，或者标题含"django"的文章
Article.objects.filter(
    Q(price__gt=100, status='published') | Q(title__icontains='django')
)
# NOT 查询：排除已删除和草稿
Article.objects.filter(~Q(status__in=['deleted', 'draft']))
```

# 三、视图、路由与模板

## 14. 函数视图（FBV）和类视图（CBV）有什么区别？如何选择？

**精简回答**：

| 对比维度 | FBV（函数视图）      | CBV（类视图）          |
| -------- | -------------------- | ---------------------- |
| 定义方式 | `def view(request):` | `class MyView(View):`  |
| 代码复用 | 较低，需手动抽取函数 | 较高，通过继承和 Mixin |
| 适用场景 | 简单、逻辑单一的视图 | 复杂、需要复用的场景   |
| 可读性   | 简单直观             | 需理解继承链和 MRO     |

**常用类视图**：

| 类视图       | 用途             |
| ------------ | ---------------- |
| `ListView`   | 展示对象列表     |
| `DetailView` | 展示单个对象详情 |
| `CreateView` | 处理对象创建表单 |
| `UpdateView` | 处理对象更新表单 |
| `DeleteView` | 处理对象删除     |
| `FormView`   | 处理通用表单     |

**选择建议**：
- 简单页面（如 FAQ、关于我们）用 FBV
- 需要标准 CRUD 操作时，用对应的通用类视图
- 需要高度定制、混合多个功能时，使用 CBV + Mixin

## 15. `@login_required` 装饰器和 `LoginRequiredMixin` 有什么区别？

**精简回答**：

| 对比     | `@login_required`         | `LoginRequiredMixin`                           |
| -------- | ------------------------- | ---------------------------------------------- |
| 适用视图 | FBV                       | CBV                                            |
| 使用方式 | 装饰器：`@login_required` | 继承：`class MyView(LoginRequiredMixin, View)` |
| 配置     | 装饰器参数                | `login_url` 类属性，更灵活                     |

```python
# 方式1：FBV + 装饰器
from django.contrib.auth.decorators import login_required

@login_required
def profile(request):
    return render(request, 'profile.html')

# 方式2：CBV + Mixin
from django.contrib.auth.mixins import LoginRequiredMixin

class DashboardView(LoginRequiredMixin, View):
    login_url = '/accounts/login/'   # 可选，自定义登录页
    redirect_field_name = 'next'     # 可选，自定义重定向参数
    def get(self, request):
        return render(request, 'dashboard.html')
```

## 16. Django 路由系统如何设计？如何处理大型项目的 URL 分发？

**精简回答**：

**基础用法**：
```python
# urls.py
from django.urls import path, include, re_path
from . import views

urlpatterns = [
    path('articles/', views.article_list, name='article_list'),           # 精确匹配
    path('articles/<int:article_id>/', views.article_detail, name='article_detail'),
    path('articles/<slug:slug>/', views.article_detail_by_slug),         # slug匹配
    re_path(r'^articles/(?P<year>[0-9]{4})/$', views.year_archive),      # 正则匹配
]
```

**大型项目推荐做法**：
- 每个 App 维护自己的 `urls.py`，主路由用 `include()` 引入
- 使用 **命名空间** 区分不同 App 的同名路由
- 使用 `app_name` 和 `namespace` 避免 URL 冲突

```python
# 主 urls.py
urlpatterns = [
    path('blog/', include(('blog.urls', 'blog'), namespace='blog')),
    path('shop/', include(('shop.urls', 'shop'), namespace='shop')),
]

# 模板中使用
<a href="{% url 'blog:post_detail' post.id %}">阅读文章</a>
<a href="{% url 'shop:product_detail' product.id %}">查看商品</a>
```

**Path 转换器类型**：`str`、`int`、`slug`、`uuid`、`path`

```python
from django import template

register = template.Library()

@register.filter(name='cut')
def cut(value, arg):

```

```django
{% load custom_filters %}
```

```python
@register.simple_tag
```

# 四、中间件与安全

## 18. 什么是 Django 中间件？如何自定义中间件？

**精简回答**：中间件是处理 Django 请求和响应的钩子框架，在请求到达视图前和响应返回客户端前进行全局处理。

Django 默认中间件的作用：

| 中间件                     | 作用                         |
| -------------------------- | ---------------------------- |
| `SecurityMiddleware`       | 安全检查（HSTS、XSS 防护等） |
| `SessionMiddleware`        | 会话管理（Session ID 处理）  |
| `CsrfViewMiddleware`       | CSRF 防御                    |
| `AuthenticationMiddleware` | 用户认证关联                 |
| `CommonMiddleware`         | URL 重写、禁止访问等通用处理 |

**自定义中间件方法**：

```python
# myapp/middleware.py
class SimpleMiddleware:
    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):
        # process_request：请求到达视图前执行
        print(f"请求路径: {request.path}")

        response = self.get_response(request)

        # process_response：响应返回前执行
        response['X-Custom-Header'] = 'My Value'
        return response
```

中间件还可以定义其他钩子方法：

| 方法                                                         | 执行时机       | 用途                   |
| ------------------------------------------------------------ | -------------- | ---------------------- |
| `process_request(self, request)`                             | 路由前         | 身份验证、IP 黑名单    |
| `process_view(self, request, view_func, view_args, view_kwargs)` | 视图前         | 权限检查、请求预处理   |
| `process_exception(self, request, exception)`                | 视图抛出异常时 | 统一错误处理、异常上报 |
| `process_template_response(self, request, response)`         | 模板响应时     | 上下文增强             |

```python
# settings.py
MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',
    'myapp.middleware.SimpleMiddleware',    # 添加自定义中间件
    # ... 顺序重要！
]
```

## 19. Django 如何防止 CSRF 攻击？

**精简回答**：Django 内置 CSRF 防护机制，原理是为每个用户会话生成唯一的 CSRF token，并验证每个非安全方法请求是否携带该 token。

**工作原理**：
1. 用户会话开始时生成 CSRF token
2. 所有 `POST`、`PUT`、`DELETE` 表单自动渲染携带 `{% csrf_token %}` 的隐藏字段
3. 提交请求时，服务器校验 token 是否匹配

```django
{# 表单中添加 CSRF token #}
<form method="post">
    {% csrf_token %}
    <input type="text" name="title">
    <button type="submit">提交</button>
</form>
```

```javascript
// AJAX 请求携带 CSRF token
fetch('/api/submit/', {
    method: 'POST',
    headers: {
        'X-CSRFToken': getCookie('csrftoken'),  // 从 cookie 获取
        'Content-Type': 'application/json'
    },
    body: JSON.stringify(data)
})
```

**全局禁用 CSRF**（不推荐）：
```python
# 对特定视图禁用
from django.views.decorators.csrf import csrf_exempt

@csrf_exempt
def api_webhook(request):
    return HttpResponse("OK")
```

## 20. Django 如何防护 XSS 和 SQL 注入？

**精简回答**：

**XSS 防护**：Django 模板系统自动转义变量输出。`{{ user_input }}` 会被转义为 HTML 实体，防止恶意脚本执行。需要输出 HTML 时需显式使用 `|safe` 过滤器或 `{% autoescape off %}`，应谨慎使用。

```django
{# 变量被自动转义 #}
<div>{{ user_comment }}</div>       <!-- <script>...</script> → &lt;script&gt;... -->

{# 谨慎使用 safe：仅当内容可信时 #}
<div>{{ trusted_html_content|safe }}</div>
```

**SQL 注入防护**：Django ORM 对所有查询参数进行参数化，从根本上防止 SQL 注入。永远不要直接拼接 SQL 语句：

```python
# ❌ 危险！不要这样做！
cursor.execute(f"SELECT * FROM users WHERE name = '{user_input}'")

# ✅ 安全
User.objects.filter(name=user_input)                    # ORM 方式
cursor.execute("SELECT * FROM users WHERE name = %s", [user_input])  # 原生SQL也需参数化
```

## 22. Django 缓存如何配置？有哪些缓存后端？

**缓存后端**：

| 后端           | 配置 BACKEND                                        | 适用场景      |
| -------------- | --------------------------------------------------- | ------------- |

```python
        'OPTIONS': {'CLIENT_CLASS': 'django_redis.client.DefaultClient'}
    }
}
```

## 23. 数据库查询有哪些性能优化技巧？

**精简回答**：

| 优化策略      | 实现方式                                  | 效果                         |
| ------------- | ----------------------------------------- | ---------------------------- |
| 避免 N+1      | `select_related()` / `prefetch_related()` | 查询次数从 N+1 降到 1 或 2   |
| 只取必要字段  | `only()` / `defer()` / `values()`         | 减少网络传输和内存占用       |
| 使用索引      | 模型中添加 `db_index=True`                | 查询速度提升数倍到数十倍     |
| 批量操作      | `bulk_create()` / `bulk_update()`         | N 条 INSERT 从 N 次降到 1 次 |
| 使用聚合      | `annotate()` / `aggregate()`              | 避免在 Python 层循环计算     |
| 避免 COUNT(*) | 缓存计数或使用 `exists()` 判断存在性      | 减少大表扫描                 |

```python
# 批量创建（N次INSERT → 1次）
books = [Book(title=f'Book {i}') for i in range(1000)]
Book.objects.bulk_create(books, batch_size=200)

# 判断存在性（不推荐 .count() > 0）
if Articles.objects.filter(status='published').exists():  # 更高效
    pass

# 使用聚合而非循环计算
total = Order.objects.aggregate(total_amount=Sum('amount'))['total_amount']
```

## 25. 什么是 DRF？序列化器（Serializer）的作用是什么？

**精简回答**：DRF 是 Django 官方的 RESTful API 框架，简化 API 开发，提供强大的序列化、认证、权限、分页、限流等组件。

序列化器是 DRF 的核心组件，负责：将 QuerySet/模型实例转换为 JSON/XML（序列化）；将请求数据转换为 Python 对象并完成验证（反序列化）。

```python
from rest_framework import serializers
from .models import Article

class ArticleSerializer(serializers.ModelSerializer):
    class Meta:
        model = Article
        fields = ['id', 'title', 'content', 'created_at', 'author']

    # 自定义验证
    def validate_title(self, value):
        if len(value) < 5:
            raise serializers.ValidationError("标题长度至少5个字符")
        return value
```

```python
# 视图中使用
from rest_framework import generics

class ArticleListCreateView(generics.ListCreateAPIView):
    queryset = Article.objects.all()
    serializer_class = ArticleSerializer
```

## 28. ViewSet 和 GenericView 的区别？

**精简回答**：

| 对比     | GenericView              | ViewSet                               |
| -------- | ------------------------ | ------------------------------------- |
| URL 配置 | 每个 action 单独配置路由 | 用 `DefaultRouter` 自动生成 CRUD 路由 |
| 代码量   | 较多                     | 较少                                  |
| 适用场景 | 自定义 action 较少时     | 标准 CRUD 场景                        |

```python
# GenericView
from rest_framework.generics import ListCreateAPIView, RetrieveUpdateDestroyAPIView

class ArticleList(ListCreateAPIView):
    queryset = Article.objects.all()
    serializer_class = ArticleSerializer

class ArticleDetail(RetrieveUpdateDestroyAPIView):
    queryset = Article.objects.all()
    serializer_class = ArticleSerializer

# urls.py
urlpatterns = [
    path('articles/', ArticleList.as_view()),
    path('articles/<int:pk>/', ArticleDetail.as_view()),
]

# ViewSet
from rest_framework.viewsets import ModelViewSet

class ArticleViewSet(ModelViewSet):
    queryset = Article.objects.all()
    serializer_class = ArticleSerializer

# urls.py（自动生成列表和详情路由）
router = DefaultRouter()
router.register('articles', ArticleViewSet)
urlpatterns += router.urls
```

## 30. Django Channels 是什么？WebSocket 如何实现？

**精简回答**：Channels 是 Django 的官方扩展，为 Django 添加了 WebSocket、HTTP2 和异步任务支持，让 Django 能够处理长连接和实时通信。

**核心概念**：

| 概念              | 说明                                     |
| ----------------- | ---------------------------------------- |
| **Consumer**      | 处理 WebSocket 连接的生命周期和消息      |
| **Channel Layer** | 管理不同实例间通信的抽象层（支持 Redis） |
| **Routing**       | 根据协议分发请求到对应 Consumer          |

**基本使用**：

```python
# consumers.py
from channels.generic.websocket import AsyncWebsocketConsumer
import json

class ChatConsumer(AsyncWebsocketConsumer):
    async def connect(self):
        self.room_name = self.scope['url_route']['kwargs']['room_name']
        self.room_group_name = f'chat_{self.room_name}'

        # 加入房间组
        await self.channel_layer.group_add(self.room_group_name, self.channel_name)
        await self.accept()

    async def receive(self, text_data):
        data = json.loads(text_data)
        # 广播消息到组内所有成员
        await self.channel_layer.group_send(
            self.room_group_name,
            {'type': 'chat_message', 'message': data['message']}
        )

    async def chat_message(self, event):
        await self.send(text_data=json.dumps({'message': event['message']}))

    async def disconnect(self, close_code):
        await self.channel_layer.group_discard(self.room_group_name, self.channel_name)
```

**部署方式**：
- 使用 `daphne` 作为 ASGI 服务器
- 使用 `redis` 作为 Channel Layer 后端
- 推荐搭配 Nginx 反向代理，配置 WebSocket 升级头

## 33. 说说你项目中最复杂的 Django 查询或优化经历？

> 实际面试中需结合真实项目经历回答，以下提供一个示例框架：

**示例场景**：某内容平台需要实现"推荐列表"功能，需综合多种因素排序——发布时间、点赞数、用户兴趣标签匹配度、作者权重等，同时还要避免重复推荐。

**技术难点**：
1. 多条件动态排序（全文搜索 + 多种权重计算）难以通过 ORM 链式调用高效实现
2. 标签匹配涉及多对多关联，常规查询产生 N+1 问题
3. 百万级数据量下，分页查询响应缓慢（OFFSET 深分页问题）

**解决方案**：
1. 使用 `Q()` 对象构建动态过滤条件 + `annotate()` 添加计算字段（标签匹配分数）
2. 使用 `select_related()` 和 `prefetch_related()` 预加载关联数据
3. 优化分页：用 `keyset` 分页（`WHERE id > last_id ORDER BY id LIMIT 20`）替代 OFFSET
4. 引入 Redis 缓存热点数据，同时结合搜索引擎（Elasticsearch）处理全文检索

**最终效果**：接口响应时间从 800ms 降至 150ms，数据库查询次数从 30+ 次降至 2 次。

## 34. 常见面试陷阱：如何避免生产环境出现数据库炸裂？

**精简回答**：

**预防措施**：
1. **索引检查**：使用 `./manage.py shell` 执行 `EXPLAIN` 分析查询性能，确保关键字段有 `db_index=True`
2. **连接池配置**：数据库最大连接数不足时，使用 `CONN_MAX_AGE` 启用持久连接
3. **缓存降级**：使用 `django.core.cache` + Redis 缓存热数据，配置本地缓存（如 LRU）作为二级缓存
4. **查询优化**：生产环境开启 `django.db.backends` 日志，分析慢查询
5. **读写分离**：使用 `django.db.router` 配置主从路由
6. **熔断限流**：使用 `django-ratelimit` 限制高频请求，配合 Nginx 限流
